# Language Adaptation

Use this reference when writing X copy in any language, translating/adapting posts, or matching a multilingual account voice. The skill is language-general: Chinese and English have extra notes because they are common in source examples, not because other languages are secondary.

## Language Selection

Follow this order:

1. Use the language the user explicitly requests.
2. If no target language is given, match the user's message language.
3. If the user provides source material in one language but asks for an audience in another, adapt for the audience language rather than translating literally.
4. If the account normally code-switches, preserve code-switching only where it sounds natural to that audience.
5. If the target language is ambiguous, ask one concise question before drafting.

## Adapt, Do Not Translate

For X, direct translation often fails. Adapt:

- hook mechanism
- cultural references
- idioms
- sentence rhythm
- level of formality
- CTA style
- humor and irony
- technical vocabulary

Keep facts stable: names, numbers, product claims, dates, and evidence.

## Universal Checks

For any language:

- First line should be clear without context.
- Avoid generic AI structure and empty summary endings.
- Use concrete situations, not abstract categories.
- Preserve the speaker's level of confidence.
- Use local punctuation and spacing norms.
- Avoid idioms you are not confident native speakers would use.
- Do not force jokes, slang, or emojis.
- If unsure about a colloquial phrase, choose plain language.

## Anti-AI Polish by Language

The shape of AI tone changes by language.

Common cross-language tells:

- over-formal introductions
- inflated adjectives
- uniform sentence length
- mechanical transitions
- generic motivational endings
- literal translation from English
- too many balanced contrasts
- claims without grounded examples

Fix with:

- shorter entry point
- one concrete situation
- local word order and rhythm
- ordinary verbs
- fewer transitions
- an ending that adds a real thought

## Worked Examples by Language

Chinese and English are shown below because they appear most in source examples — they are **not** a privileged pair. Apply the same "find the local stock openers, translationese, inflated register, and mechanical connectives" lens to Spanish, Japanese, Arabic, French, Portuguese, Indonesian, and any other target language. When you are not fluent in a language's tells, default to plainer, simpler writing rather than guessing at idiom.

### Worked example: Chinese

Watch for:

- 过度承接: "首先/其次/最后/值得注意的是"
- 宏大铺垫: "在当今快速发展的时代"
- 互联网黑话: "赋能/闭环/抓手/沉淀/认知升级"
- 翻译腔: "这不仅是 A，更是 B"
- 工程汇报腔 in casual contexts
- 小红书 AI 腔 when the target is X

Keep English product terms when the audience expects them. Do not translate common technical terms into awkward Chinese.

### Worked example: English

Watch for:

- "In today's..."
- "unlock"
- "game-changing"
- "not just X, but Y"
- "let's dive in"
- "hope this helps"
- overuse of em dashes
- generic conclusion paragraphs

Prefer plain verbs, specific situations, and smaller claims.

## Bilingual and Code-Switching

Use mixed language only when:

- the account already does it
- the audience uses those terms naturally
- the English term is the category standard
- the switch improves precision or recognizability

Avoid mixed language when it only signals sophistication. It usually reads as forced.

## Output Rule

Return the final copy in the target language. Add notes in the user's language unless the user asks otherwise.
