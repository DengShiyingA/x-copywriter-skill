## Context Inputs

Collect only what changes the copy:

| Input | Why it matters |
|---|---|
| Reader | Determines vocabulary, pain, and examples. |
| Moment | Explains why this matters now. |
| Claim | The one belief or lesson the post should land. |
| Proof | Keeps the copy credible. |
| Action | Shapes the close. |
| Voice | Prevents generic AI tone. |

## Awareness Calibration

How much a reader already knows about the problem and your solution decides how the post should open. This is the oldest idea in direct response (Eugene Schwartz named five awareness stages); the stages are public-domain references — write all copy fresh, never reuse classic ad lines. Map the reader's state to the opening move:

| Reader state | They already believe | Open with |
|---|---|---|
| Unaware | Nothing; no felt problem yet | A situation or tension that makes the problem visible. |
| Problem-aware | "I have this pain" | Name the pain precisely, then reframe its real cause. |
| Solution-aware | "Tools like this exist" | The mechanism or angle that makes yours different. |
| Product-aware | "I know your thing" | Proof, specifics, and the reason to act now. |
| Most-aware | "I'm ready" | The offer and the single next action, minimal preamble. |

Mismatched awareness is a common reason posts flop: pitching the offer to an unaware reader, or re-explaining the problem to someone ready to buy. Infer the dominant stage of the intended reader and lead accordingly.

## Voice Fingerprint

Generic founder-speak is the default failure mode. When the user supplies prior posts, a bio, or a writing sample, extract a compact fingerprint before drafting and write to it:

```text
Sentence length: short / mixed / long
Register: casual / plain-pro / technical / blunt
Person: I / we / impersonal
Punctuation habits: [em dashes? ellipses? all-lowercase? line breaks?]
Slang and emoji: [allowed set, or none]
Code-switching: [languages/terms they actually mix]
Self-disclosure: low / medium / high
Sells: softly / directly / never
Words they never use: [list]
```

Match the fingerprint instead of a generic "natural" voice. Do not professionalize a casual writer or casualize a precise one. If no sample exists, ask for one or infer conservatively and keep the voice plain rather than performed.

## External Pattern Research

When the user asks to learn from the market, study patterns without cloning posts.

Extract:

- **Trigger**: what made the topic timely or emotionally live?
- **Reader identity**: who felt personally addressed?
- **Angle**: contrarian, tactical, story, proof, teardown, prediction, or offer?
- **Proof style**: numbers, screenshots, named examples, lived story, or mechanism?
- **Conversation path**: replies, quotes, reposts, follows, clicks, or saves?
- **Voice**: calm expert, builder diary, sharp critic, analyst, operator, teacher?

Then write a synthesis like:

```text
The niche is responding to [tension].
The strongest posts use [pattern] because [reason].
For this user, adapt it by [fresh angle].
Avoid copying [specific surface pattern].
```

## Skill Design Patterns Worth Preserving

Open social and copywriting skills tend to work best when they separate these responsibilities:

- Context capture: audience, tone, product, proof.
- Creation: posts, threads, hooks, replies, repurposing.
- Planning: pillars, cadence, platform strategy.
- Analysis: performance review, pattern detection, optimization.

For this skill, keep those ideas in one lightweight workflow unless the user asks to build a larger multi-skill system.

## Hot Repo Lessons

When learning from popular repositories, borrow workflow architecture, not surface copy.

- Real-time research tools suggest that good X copy starts from recent discourse, not stale generic advice.
- Social media skill packs show that context, post writing, thread writing, repurposing, and analysis are separate jobs.
- Anti-AI writing projects show that final polish should check rhythm, specificity, and voice fidelity.
- X automation projects are useful for search/monitoring/publishing, but the copy skill should not automate actions unless explicitly asked.
- Chinese tweet-writing projects emphasize "collection value": a post should contain data, judgment, a useful move, or a memorable line.

## Hook Lab

Draft hooks by mechanism, not by formula.

### Tension Hook

Use when the audience believes one thing but reality is more nuanced.

Pattern:

```text
Everyone optimizes for [obvious thing].
The constraint is usually [less obvious thing].
```

### Specific Result Hook

Use when there is credible proof.

```text
[Audience] got [result] after changing [specific behavior].
The interesting part: [unexpected mechanism].
```

### Mistake Hook

Use when teaching from experience.

```text
I used to think [old belief].
That made me [bad decision].
Now I look for [better signal].
```

### Situation Hook

Use when the reader is in a recognizable moment.

```text
When [situation], don't start with [common tactic].
Start with [better first move].
```

### Contrarian Hook

Use only when the claim is defensible.

```text
[Popular tactic] is overrated for [specific audience].
It works only when [condition].
```

## Hook Tournament

Do not ship the first hook. Generate several across different mechanisms, score them, and publish only the winner (offer alternates only if the user asked for options). This is the single habit that most separates strong copy skills from generate-and-stop ones.

1. Draft 5-8 first lines using different mechanisms from the Hook Lab — not 8 variations of one idea.
2. Score each, 1-5, on four checks:
   - **Stop**: would the intended reader's thumb actually pause?
   - **Stake**: is there tension, a promise, or something at risk?
   - **Specificity**: a concrete noun/number/situation, not a category?
   - **Truth**: can the body honestly deliver what the line implies?
3. Kill any hook that scores low on Truth regardless of its other scores — an overpromise that the body can't pay back trains negative feedback.
4. Take the top one or two; if the best still feels generic, write one more round sharpening audience or proof.

The first line is also the part the ranking system gets the most signal from (it drives dwell and the decision to expand), so spend disproportionate effort here.

## Post Shapes

### 1. Useful Observation

Best for authority and reposts.

```text
[Observation]

Most people notice [surface].
The useful signal is [deeper pattern].

[Example]
```

### 2. Small Story

Best for founder voice and trust.

```text
[Moment]

[What you expected]
[What happened]
[What changed]

Lesson: [portable insight]
```

### 3. Mini-Framework

Best for saves, reposts, and follows.

```text
To solve [problem], separate:

1. [Layer A]
2. [Layer B]
3. [Layer C]

Most teams skip [layer].
That's why [consequence].
```

### 4. Proof Post

Best for launches, offers, and authority.

```text
We learned [claim] from [proof source].

What changed:
- [before]
- [after]
- [mechanism]

The lesson: [reader takeaway]
```

### 5. Conversation Starter

Best for replies.

```text
I'm torn on [specific tradeoff].

Option A: [benefit/cost]
Option B: [benefit/cost]

If you've dealt with this, what did you choose?
```

### 6. Clean Offer

Best for conversion without hype.

```text
I made [thing] for [reader].

It helps with [specific job].

You get:
- [deliverable]
- [proof or mechanism]
- [risk reducer]

[clear next action]
```

## Thread Design

A thread should move the reader through a sequence, not stretch one post into fragments.

Use this arc:

1. **Promise**: what the reader will understand or be able to do.
2. **Problem**: what they are getting wrong or missing.
3. **Frame**: the mental model.
4. **Steps or evidence**: one useful idea per post.
5. **Example**: make the abstraction concrete.
6. **Close**: recap, next action, or conversation prompt.

Thread rules:

- Tweet 1 should be useful even if nobody opens the thread.
- Each post should justify its place.
- Avoid numbering if the thread is only 2-3 posts.
- Do not end every thread with a generic follow CTA.

Before delivering a thread, run a two-part integrity audit:

- **Standalone test**: could each post be screenshotted alone and still make sense? Because of candidate isolation, posts can surface individually — none should depend on the previous one to be readable.
- **Flow test**: read the posts in order with the hooks removed. Does each one advance the journey, or are some restating the same beat? Cut or merge anything that does not move forward.

## Replies and Quote Tweets

The best replies add a layer:

- Add missing context.
- Offer a counterexample.
- Translate the idea to another audience.
- Share a practical implementation detail.
- Ask a precise follow-up.

Avoid:

- "Great point"
- Agreement with no new information
- Hostile dunking unless the user's brand explicitly calls for sharp debate
- Hijacking the original post with unrelated promotion

Quote tweets should answer: "Why should my audience see this through my lens?"

## Offer Posts

Before writing, locate the offer lever:

| Lever | Copy move |
|---|---|
| Dream outcome | Name the concrete result. |
| Believability | Add proof, mechanism, or scope. |
| Time | State the timeline only if real. |
| Effort | Explain what becomes easier. |
| Risk | Clarify guarantee, trial, refund, demo, or limitation. |

Bad offer posts make loud promises. Strong offer posts make a specific promise believable.

## Repurposing Long-Form Content

Convert source material into X-native atoms before writing.

Extraction pass:

- Thesis: the one idea worth remembering.
- Proof: stats, examples, quotes, screenshots, case details.
- Tensions: where the source challenges common belief.
- Steps: any process that can become a thread.
- Lines: short phrases worth rewriting into hooks.
- Audience: who should care and why now.

Output options:

- 1 sharp standalone post
- 1 thread
- 3 quote-style insight posts
- 3 reply prompts for joining conversations
- 1 offer or newsletter CTA post

Do not summarize the source mechanically. Translate it into a social idea with its own payoff.

## Critic Gate

Before a draft is delivered, review it once as a skeptical reader, not as its author. Score five things, 1-5:

- **Hook**: does the first line earn the second?
- **One idea**: is the post about a single clear thing?
- **Proof**: is there a number, example, mechanism, or honest limit — not just adjectives?
- **Action fit**: is one likely reader response obvious and earned?
- **Voice**: does it sound like the user, not a generic AI account?

If any item scores 1-2, rewrite that dimension before delivering — do not ship a draft with a known weak spot and a note apologizing for it. The gate is internal; the user sees the improved draft, not the scores, unless they asked for an audit. The point is a forced rewrite, not a report.

## Performance Feedback Loop

When metrics are available, diagnose before rewriting.

| Signal | Likely issue | Copy response |
|---|---|---|
| Impressions low | Weak retrieval, timing, topic identity, or early engagement. | Sharpen topic/audience and post when reachable. |
| Dwell low | First line or structure failed to earn reading. | Rewrite hook and reduce setup. |
| Likes but no replies | Easy agreement, no conversation opening. | Add tradeoff, question, or specific scenario. |
| Replies but negative tone | Bait, ambiguity, or overclaiming. | Add nuance, proof, and cleaner boundaries. |
| Reposts low | Not useful enough for the reader's audience. | Turn claim into a reusable frame. |
| Clicks low | CTA is premature or value unclear. | Give native value before asking for the click. |
| Follows low | One-off content, no visible point of view. | Tie post to a repeatable account thesis. |

## Anti-AI Polish Position

Do not run anti-AI polish before the idea is clear. The right order is:

1. audience
2. angle
3. proof
4. structure
5. X distribution check
6. anti-AI polish

Polishing a weak idea only makes the weak idea smoother.

## Rewrite Moves

Use these instead of light editing:

- **Narrow the reader**: from "people" to a role or situation.
- **Name the stakes**: what changes if they ignore this?
- **Add a mechanism**: why does the advice work?
- **Replace hype with proof**: number, story, comparison, or example.
- **Cut the preamble**: start where the tension starts.
- **Split crowded posts**: one idea per post, one journey per thread.
- **Change the action**: if the CTA feels forced, switch to reply, follow, or save-worthy value.

## Local Voice Notes (worked example: Chinese)

Every language has its own local voice habits, filler register, and overused jargon. The general move is the same in any market: write compact, lead with one judgment, drop imported buzzwords the audience does not actually speak, and keep standard product terms only when they are the local norm. See [language-adaptation.md](language-adaptation.md) for the full per-language method. The Chinese notes below are one worked example of applying it.

For Chinese posts:

- Use direct, compact sentences.
- Avoid overusing "赋能", "颠覆", "闭环", "抓手", "私域", "认知升级" unless the user's audience genuinely speaks that way.
- Strong openings often work as a tension pair: "大家都在 X，其实真正的问题是 Y。"
- Keep English product terms when they are standard in the audience, but explain uncommon acronyms once.
- For founder IP, balance personal story with business takeaway; avoid diary-only posts.
